# Portable agent baseline — 2026-09-03

This is a measured harness-compatibility baseline, not a universal model
ranking. Every result in the table used the unchanged fixture from commit
`864230d8099302b48c074e4b5cebcba4c5caa79e` in an isolated Docker container.
The container root was read-only, Linux capabilities were dropped, and only
the fixture workspace and a temporary harness home were writable. Temporary
credential copies were removed after each run.

Claude Code also reported a small Claude Haiku 4.5 auxiliary call, zero web
searches, and the Opus 5 model for the implementation. The account was on a
subscription; the dollar amount above is the CLI's list-cost estimate, not a
claim that an incremental charge occurred. OpenCode used local compute, whose
electricity and hardware cost were not metered.

## Deterministic proof

All three completed runs:

- created `workspace/` from `inputs/example/repository`;
- changed only `workspace/catalog.py`;
- left `README.md` and `test_catalog.py` byte-identical;
- added no extra files or symlinks; and
- passed an independent rerun of `./verify.sh workspace`.

```text
Ran 1 test in 0.000s

Verification passed: scope and acceptance checks succeeded.
```

## Implementation differences

Codex used a compact loop, indexed `row["name"]`, and sorted with
`str.casefold`. Claude Code used a comprehension, defaulted a missing name to
an empty string, called `strip()` twice, and sorted with `str.casefold`.
OpenCode/Qwen3 Coder used the longest implementation, explanatory comments,
and `str.lower`. All three satisfy the fixed acceptance test without mutating
input. The fixture does not specify missing or non-string names or the Unicode
case-folding boundary, so those differences must not be used to declare a
universal winner.

## Blocked attempts

The first host-native Codex attempt was blocked before repository commands by
the host's nested Bubblewrap networking restriction. The successful run used
the external Docker boundary described above and is the result in the table.

Gemini CLI authenticated far enough to receive Google's response, but Google
rejected the personal account tier as an unsupported client and directed it to
Antigravity. It created no workspace and made no fixture changes.

The pinned OpenCode run used OpenCode 1.18.27 with the already-installed local
Ollama model `qwen3-coder:latest` (digest prefix `06c1097efce0`): 30.5B
parameters, Q4_K_M quantization, 262,144-token declared context, Apache-2.0.
It first tried `python -m pytest` and `python3 -m pytest`, although the pack
requires no pytest dependency. Running the test directly created a bytecode
cache; the required verifier rejected it, after which the agent removed the
cache and reran the verifier successfully. No dependency was installed and no
web tool was enabled. This recovery is useful evidence, but the extra commands
and temporary scope failure count against instruction efficiency.

## What this proves

The canonical instructions and verifier work unchanged with the tested Codex,
Claude Code, and OpenCode versions. The task is intentionally too small to rank
code quality, reliability on real repositories, or value for money. A harder
fixed fixture and the missing Gemini, Devstral Small 2, and Qwen3-Coder-Next
runs are required before making those claims.
